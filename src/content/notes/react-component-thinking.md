在项目里设计组件时，我会先问自己三个问题。

## 1. 这个组件的职责是不是单一

如果一个组件同时负责拉数据、处理状态、展示 UI 和做权限判断，它的维护成本会很快变高。

## 2. 它复用的是“结构”还是“业务”

有些组件看起来复用了，但其实只是视觉相似，行为完全不同。这样的抽象通常会让后面改动更痛苦。

## 3. 它最重要的输入和输出是什么

把 props 和事件接口想清楚，后面很多问题都能提前避免。

## 适合在简历站点里怎么写

这类笔记不一定要很长，但要尽量让人看出你是如何思考工程设计的，而不是只堆术语。
