一篇面经可能是一段文字、几张截图，也可能是一段面试录音。读完以后，如果只留下收藏链接，下次准备面试仍然要从原帖重新找题。

我近期开发的 Gleaner 和 Interview Bank，围绕这条路径分工：发现素材、整理题库，再把题目放到电脑和手机上阅读与复习。[在线测试版](https://exist.qd.je/) 已开放公开资料阅读。

## Gleaner：先把素材和来源收好

[Gleaner](https://github.com/EXIST-D/Gleaner) 通过本机 MediaCrawler 连接小红书、抖音、B 站和知乎，并直接读取牛客公开面经列表。它按平台与帖子 ID 去重，再用规则标记疑似面经、题目合集、广告和待判断内容。

这一步的产物是素材包：正文、图片或录音，配上来源信息、manifest 和 HANDOFF 文档。规则只做初筛，人工标签会被保留；遇到验证或登录过期时，采集会说明原因并停止或跳过对应平台。

## Interview Bank：把材料变成可维护的题目

[Interview Bank](https://github.com/EXIST-D/Interview-bank) 交给 Agent 理解截图和转写稿，由 Python CLI 负责校验与提交。原题、追问关系、公司、轮次和来源分别保存，同义问法合并后仍能回看出现记录。

相似题不一定能合并。同一个关键词，在不同语言、版本和业务场景里，可能对应不同的考点。候选检索用于缩小比较范围，Agent 判断题意，不确定的交给用户裁决。

参考答案也保留出处。官方文档支持了哪些要点、哪些部分仍是待复核草稿，应当能被看见。“有来源”与“经过人工审阅”分别记录。

## 在线阅读器：让整理结果随时能用

在 [exist.qd.je](https://exist.qd.je/) 可以免登录浏览八股资料、公开面经与学习资料。个人面经、笔记、收藏和练习记录需要登录，当前仍是在线测试版。

电脑端把列表与正文并排，支持专注阅读和独立笔记面板；手机端可以全屏阅读、切换上一题和下一题，也可以随机选题、先想再看。复习队列支持简单间隔与可选 FSRS 算法。

这些功能让整理出的题库进入日常使用。复习算法给出的是下一次复习时间，不是对掌握程度或学习效果的保证。

## 为什么采集题库与个人题库分开

批量采集到的出现次数和个人经历是两种记录。混在一起之后，很难判断一题是自己反复遇到，还是采集范围扩大带来的重复。

因此 Gleaner 默认连接独立采集题库；需要补充到个人题库时，再导出题目包，经重复候选审阅后导入。三个环节可以衔接，但目前仍需要 Agent 处理与人工确认，不是无人值守地向线上题库持续灌入数据。
